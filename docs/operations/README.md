### How to read validation labels

**Historically observed** means captured on a dated system. **Fixture-tested** applies only to the stated test scope. **Syntax-reviewed** checks command form. **Documentation-reviewed** checks documented semantics. **Runtime-pending** means successful execution still needs evidence. **Blocked by environment** records a missing tool, access, or capability. Chapter shorthand differs: Docker **D** and other chapters’ **S** describe review with runtime pending, **F** plus a batch number identifies fixture results, and **B15** marks the route query blocked by netlink permissions. The chapter’s local legend and the [QA matrix](validation-matrix.md) specify the exact scope.

For a known historical incident, see the handoff table in HOMELAB-RESUME-HERE.md (private research record). The original host diagnostic quick reference follows.

A **mount point** is the directory where a filesystem becomes accessible. A **bind mount** exposes an existing directory tree through another path. A **container network namespace** is the network view a container uses. A **listener** is a socket waiting for traffic. The **system journal** stores messages from the kernel and services on systemd hosts.

Work on an authorized host and note the time and time zone before collecting output. Substitute your real paths, disks and container names. All commands here query state. They do not mount storage, change Docker settings, start SMART tests, or restart services. A SMART query may wake a sleeping disk. Run unprivileged commands as your regular account. Docker daemon access can confer host-level privileges even when the requested operation is read-only. Use an already authorized account. Keep raw logs and hardware identifiers private.

| Goal and command | What to expect and what to check next | Prerequisites and access |
| --- | --- | --- |
| **Identify storage.** `lsblk -o NAME,TYPE,SIZE,FSTYPE,MODEL,MOUNTPOINTS` lists disks and their child partitions. Use it before selecting a device for SMART. | Example: `sdb disk 7.3T` with `sdb1 part 7.3T ext4 /srv/media`. Blank filesystem on the parent disk is routine when its child contains the filesystem. A missing expected partition or mount warrants an identity and kernel-log check. Device names can change across boots. | Linux and util-linux. Normally no elevation. |
| **Check live mount.** `findmnt --target /srv/media -o TARGET,SOURCE,FSTYPE,OPTIONS` identifies the filesystem currently containing the path. | Example: `/srv/media /dev/sdb1 ext4 rw`. If expected separate storage resolves to `TARGET=/`, investigate before copying or cleaning files. A bind may display its backing filesystem type or a source subtree. To test whether the path itself is a mount point, use `findmnt --mountpoint /srv/media -o TARGET,SOURCE,FSTYPE,OPTIONS` (same prerequisites). An ordinary directory can have a successful target lookup and no exact-mount match. | util-linux and an existing path. Normally no elevation. |
| **Check persistence.** `findmnt --fstab -o TARGET,SOURCE,FSTYPE,OPTIONS` displays configured mounts. `findmnt --verify --verbose` checks the table for issues without attempting mounts. | Example: `/srv/media UUID=[redacted] ext4 defaults`. If the intended entry is missing or verification reports warnings, compare its source and target to the live mount. A clean check alone does not prove the next boot will mount successfully. The test also depends on device and path visibility. | util-linux and readable fstab. Normally no elevation, though inaccessible devices or paths can limit checks. |
| **Check free space.** `df -hT /srv/media` shows human-readable filesystem totals and type. `df -B1 /srv/media` shows byte-scale totals for comparisons. | Example: `ext4 7.3T 5.1T 2.2T 70% /srv/media` (selected columns). Verify the mount first. Compare Used values for the same filesystem across comparable windows. Concurrent writes and other changes can affect the delta. A file-size sum does not establish filesystem savings. | GNU coreutils and a valid path. Normally no elevation. |
| **Check drive health.** `sudo smartctl -a /dev/sdb` reads identity, health, attributes and available logs. | Example: `PASSED; 197=0; 198=4; 199=0` (selected fields). PASS can coexist with recorded errors. Compare raw values for the same model and identity over time. If SMART is unavailable, check device access and adapter support. | smartmontools, correct whole disk and a supported interface. Usually requires sudo. |
| **Check container state.** `docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'` lists running and stopped containers. | Example: `jellyfin  Up 2 hours (healthy)  0.0.0.0:8096->8096/tcp`. A restart loop or exit suggests checking logs and dependencies. An empty Ports field can be expected in shared namespace arrangements. Healthy is scoped to the configured healthcheck. | Docker CLI, running Engine and authorized daemon access. No sudo if already authorized. |
| **Check network mode and related fields.** `docker inspect --type container --format 'mode={{.HostConfig.NetworkMode}} networks={{json .NetworkSettings.Networks}} ports={{json .NetworkSettings.Ports}}' jellyfin` shows effective Engine metadata. | Example: `mode=media_default networks={...} ports={"8096/tcp":[...]}`. Compare the app and proxy. If the mode references another container, inspect that container as well. An empty Networks field alone does not prove isolation. Output may contain addresses. | Docker and authorized daemon access. No sudo if already authorized. |
| **Check listeners.** `ss -lntu` lists TCP listeners and UDP sockets without using DNS names. | Example: `tcp LISTEN ... 127.0.0.1:8096` indicates a host loopback bind. A loopback bind is local to that namespace. A wildcard bind covers the corresponding address family in that namespace. TCP shows LISTEN. A bound connectionless UDP socket can show UNCONN, which is normal. To separate protocols use `ss -lnt` (TCP) or `ss -lnu` (UDP), with the same access. Check stderr as well as the exit code. A restricted environment can list TCP sockets while reporting a netlink permission error. Host Docker NAT publication may exist without a matching host userspace listener. Compare the Docker mapping and client path. | iproute2 on Linux. Normally no elevation for address and port listing. |
| **Review application logs.** `docker logs --since 30m --tail 100 --timestamps jellyfin` reads recent container output. | Example: `2026-01-01T12:00:00Z server started`. Look for first failure, dependency error, fallback and later success in the same time window. If output is empty, check log driver, container name and the app's own log location. | Docker with accessible container logs, authorized daemon access. No sudo if already authorized. |
| **Review kernel and system logs.** `sudo journalctl -k -b --since '1 hour ago' --no-pager` shows current-boot kernel events. `sudo journalctl -u docker --since '1 hour ago' --no-pager` shows the Docker system unit's journal. | Example: `ata2: hard resetting link` or `docker.service: Started`. Correlate time, device identity and boot with incident evidence. A successful exit with `-- No entries --` and `No journal files were found` means there was no readable journal in that environment. Empty output can also reflect retention, boot scope, permissions, or a different rootless unit. | systemd journal. Elevated access used for consistent visibility. Authorized journal readers may omit sudo. |

All example fragments above are synthetic and are shortened for readability. Keep original output when documenting an incident. Distinguish an empty result from a successful test. Batch 11 verified filesystem checks against a private tmpfs fixture and used synthetic test files for supporting checks. Batch 12 checked TCP and UDP fixture sockets separately. The results included a netlink warning, so full enumeration remains unverified. An empty journal directory returned success with no records, while a permission-restricted directory returned an error. Block-device inventory, SMART, Docker and populated journal behavior still require an isolated test host. A command failure such as exit 127 or permission denied is a diagnostic-environment result. Service health requires separate evidence.
